# Recruitment lettering filter

Recruitment rankings and exports exclude profiles with known usernames or display names containing Unicode letters outside ASCII A–Z/a–z, including accented, combined-accent and decorative letters. Emojis, punctuation and numbers alone are allowed. This is a lettering rule, not a nationality classifier. Names are never transliterated into different accounts.

The filter is applied when reading saved rankings, so existing scans with saved display names are covered without deleting their results. Duplicate league entries cannot hide a flagged name. Filtered creators are omitted from the selectable rankings, available/premium/regular lists and new Backstage queues. Current-scan exclusions also apply to displayed availability changes, visible confirmed-message rows and copy/CSV/TXT exports. Original contact history remains intact for duplicate-send prevention.

API fields `name`, `nickname`, `display_name` and `displayName` are checked when present. A missing nickname cannot be inferred from an ASCII username. In pasted-list messaging, the profile's visible nickname must be read before opening Message; non-A–Z letters or an unreadable nickname stop that creator without sending. The Send wrapper also enforces the block. Reopen the local messaging panel after this update so it loads the changed Python modules. No messages or invitations are sent as part of testing or deployment.

Old historical records outside the loaded scan that contain no nickname cannot be retrospectively classified by nickname. Their ASCII username alone is insufficient evidence. The profile check covers that case before a send is attempted. Ordinary Chrome view mode has no DOM access and cannot verify nicknames automatically; its manual Foreign tag remains available.

Future profile PDF: separate, read-only capture queue using a signed-in, inspectable browser; screenshot plus clickable username, dated diamond observations and Backstage result on each page. Missing days must remain unknown rather than zero. A three-day sort must deduplicate observations by username/creator ID and date; cumulative figures must not be summed as daily figures. Capture failures and login/CAPTCHA screens must be recorded as failures, with resume support, rather than being presented as valid profile screenshots. This PDF feature is not implemented by the lettering-filter change.

Backstage batches now read the nickname from the exact matched creator row as well. The worker submits it with the unchanged eligibility result; the server persists a separate lettering-exclusion flag and merges it into all displayed/exported rankings. Restart the checker to load this update. Checks completed by the older worker did not store their nickname and need one recheck to populate it. Available is not falsely changed to Ineligible because of a name-format rule.

The user-approved ornament pattern `.𖥔 ݁ ཐི༏ཋྀ .𖥔 ݁` is explicitly allowed (including its star-like glyph and decorative mark). The complete butterfly-like sequence is removed only for the lettering test; this does not allow arbitrary Tibetan or other foreign-script words. Emoji variation selectors remain allowed as well.

The rankings table now has a visible Foreign counter/button and dropdown filter. All includes these diagnostic rows with the nickname and exclusion reason; their actual Backstage status remains in Details. Their checkboxes are disabled, Select All skips them, and Available/Premium/Regular copies, downloads and PDF manifests still exclude them. A separate notice counts older checked results missing the saved nickname field.
